# كتالوج الخدمات الاستشارية

تطبيق ويب تفاعلي لاستعراض وإدارة **بطاقات الخدمات الاستشارية** ضمن *برنامج الاستشارات الرقمية 2026* — يعرض 48 خدمة موزّعة على 7 قطاعات ومراكز، مصنّفة حسب الأهداف الاستراتيجية والفئات ومراحل التحول الرقمي الثلاث.

> ⚠️ **الرابط نفسه هو السرّ الوحيد.** كلمة مرور الكتالوج المشتركة أُلغيت بقرار صريح، ومفتاح فكّ التشفير صار مضمّنًا في صفحة الموقع.
> عمليًا: أي شخص يصل إلى الرابط أو المستودع يستطيع قراءة كل بيانات الكتالوج، **واستخراج رمز الكتابة في GitHub** المخزَّن داخل الملف المشفّر — أي التعديل والحذف لا القراءة فقط.
> تسجيل الدخول والأدوار تنظيمية في الواجهة (JavaScript) ولا تمنع ذلك تقنيًا. **لا تضع في هذا الكتالوج بيانات لا تحتمل الانكشاف.**

---

## المزايا

- **لوحة رئيسية (Dashboard):** مؤشرات سريعة، توزيع المراحل (مخطط دائري)، الخدمات حسب القطاع، وبطاقات القطاعات والأهداف والفئات — كلها قابلة للنقر للتصفية.
- **بطاقات الخدمات:** عرض شبكي أنيق مع شارات القطاع والمرحلة والمالك و SLA.
- **بطاقة تفصيلية:** لوحة جانبية تعرض كل حقول الخدمة (الوصف، الأهداف، المتطلبات، المخرجات، المستفيدون، مبرر تصنيف المرحلة…).
- **فلترة غنية بالأزرار والبطاقات** (بدل القوائم المنسدلة): حسب القطاع، الإدارة العامة، المرحلة، الهدف، الفئة، المستفيدين، المالك، والممثل — مع بحث نصي فوري.
- **إضافة / تعديل / حذف** للخدمات، وإدارة قوائم: الإدارات العامة، ملاك الخدمات، وممثلي الخدمات (إعادة تسمية تنعكس على كل الخدمات).
- **حسابات مستخدمين وأدوار:** شاشة دخول/تسجيل بتبويبين، ولوحة **إدارة المستخدمين** لمدير النظام: اعتماد الطلبات، تغيير الدور والنطاق، تعيين كلمة مرور، إنشاء حساب مباشرةً، تعطيل أو حذف، مع بحث وتصفية ومرجع صلاحيات لكل دور.
- **حالة إتاحة الخدمة:** كل خدمة تحمل إحدى أربع حالات — **مفعلة** (متاحة ويمكن طلبها)، **قيد التفعيل** (قيد الإعداد ولم تُفتح للطلب)، **جاري التحليل** (خدمة جديدة اقترحتها إدارتها وتنتظر اعتماد مدير النظام)، أو **متوقفة (مؤرشفة)** — تظهر كقسم مستقل في الصفحة الرئيسية، وكشارة ملوّنة على كل بطاقة، وكمجموعة فلترة مستقلة. الخدمات غير المفعّلة تُعرض باهتة حتى لا تُقرأ كخدمة متاحة، ويمكن تسجيل **سبب الإيقاف / ملاحظة الحالة** في حقل مستقل يظهر في البطاقة التفصيلية.
- **تاريخ آخر تحديث** يُحدَّث تلقائيًا مع كل تعديل.
- **مظهر فاتح/داكن**، تصميم متجاوب، خط IBM Plex Sans Arabic، ودعم كامل للاتجاه من اليمين لليسار.
- **نسخ احتياطي**: تصدير/استيراد نسخة JSON، وتحديث مباشر من المستودع.

## آلية العمل — «قاعدة بيانات على GitHub»

- تُخزَّن البيانات مشفّرة في الملف `data/catalog.enc` داخل المستودع (نص مشفّر فقط، لا بيانات صريحة أبدًا).
- الملف مشفّر بمعيار AES‑256‑GCM، لكن **المفتاح مضمّن في `js/config.js`** (`catalogKey`) ويفكّ التطبيق التشفير تلقائيًا عند فتح الصفحة — لا تُطلب كلمة مرور مشتركة. التشفير هنا يمنع فهرسة محركات البحث للمحتوى، ولا يمنع من يفتح الرابط.
- **بوابة واحدة: الحساب الشخصي** — يسجّل كل شخص دخوله بحسابه (أو يطلب حسابًا جديدًا)، وعلى أساسه تُحدَّد صلاحياته:
  - **مدير النظام:** يرى ويعدّل كل شيء مباشرة، ويوافق على الحسابات الجديدة والتعديلات المُرسلة من الآخرين، ويعيّن الأشخاص كملاك/ممثلين لخدمات محددة.
  - **مالك/ممثل خدمات:** يرى ويعدّل خدمات **إدارته العامة فقط** (يختار القطاع ثم الإدارة عند التسجيل، ويعتمدهما مدير النظام). القطاع والإدارة مقفلان في نموذج الخدمة ويُفرضان من الحساب نفسه.
    - **إضافة خدمة جديدة:** تدخل الكتالوج مباشرةً بحالة **«جاري التحليل»** — يراها صاحبها ومدير النظام، ولا تُعدّ خدمة معتمدة حتى يحللها المدير ويضغط *اعتماد وتفعيل* (فتصبح «مفعلة») أو *رفض* (فتصبح «متوقفة» ولا تُحذف).
    - **تعديل أو حذف خدمة قائمة:** يذهب لقائمة "طلبات المراجعة" (🔔 في الشريط العلوي) ولا يُطبَّق على الكتالوج المشترك إلا بعد موافقة مدير النظام.
- **أول شخص يفتح الكتالوج بعد النشر يُنشئ حساب مدير النظام الأول تلقائيًا** (لا يوجد بعد أي مستخدمين).
- صلاحية الكتابة في GitHub (رمز وصول بصلاحية `Contents: Read and write`) **مُضمّنة داخل الملف المشفّر نفسه**. عند حفظ أي تغيير (بما فيها الحسابات والتعديلات المعلّقة) تُعاد كتابة الملف المشفّر في المستودع عبر GitHub Contents API. ⚠️ بما أن مفتاح فكّ التشفير صار علنيًا، فالرمز عمليًا **قابل للاستخراج من أي متصفح** — قصر صلاحياته على هذا المستودع وحده، وبدّله فور أي اشتباه.

> ⚠️ **حدود هذا النموذج:** الموقع مُستضاف كملفات ثابتة (GitHub Pages) بلا خادم خلفي، فكل شيء يجري في المتصفح. لذلك:
> - **البيانات مكشوفة لمن يملك الرابط** — المفتاح في الصفحة، ويكفي فتح أدوات المطوّر لقراءة الكتالوج كاملًا.
> - **رمز الكتابة مكشوف كذلك** — فيستطيع من استخرجه الكتابة في المستودع.
> - **الأدوار والصلاحيات تنظيمية فقط** — تنظّم عمل فريق موثوق، ولا تُعدّ ضابط وصول.
>
> لإعادة حماية حقيقية، الخيارات: إعادة تفعيل كلمة مرور يدخلها المستخدم، أو تغليف المفتاح لكل حساب بكلمة مروره الشخصية (تشفير غير متماثل عند اعتماد الحساب)، أو نقل البيانات إلى خادم/خدمة بصلاحيات فعلية.

### تدوير مفتاح فكّ التشفير
المفتاح مضمّن في `js/config.js`، فتغييره يتطلب إعادة تشفير الملف وتحديث الإعدادات معًا وإلا تعطّل الموقع:
```bash
node tools/build-data.js <catalog.json> "<المفتاح الجديد>" data/catalog.enc --write-token="<رمز الكتابة>"
# ثم حدّث CONFIG.catalogKey في js/config.js بنفس المفتاح
```

### تدوير رمز الكتابة (Rotate)
عند الحاجة لتغيير الرمز المُضمّن (مثلًا بعد انتهاء صلاحيته)، دون الحاجة لملف البيانات الصريح:
```bash
node tools/set-write-token.js data/catalog.enc "<المفتاح من CONFIG.catalogKey>" "<الرمز الجديد>"
git add data/catalog.enc && git commit -m "تدوير رمز الكتابة" && git push
```

## التطوير المحلي

```bash
# أي خادم ملفات ثابت، مثلاً:
npx serve .
# ثم افتح http://localhost:3000
```
> يجب التشغيل عبر خادم HTTP (وليس فتح الملف مباشرة) حتى يعمل جلب البيانات.

## إعادة توليد البيانات المشفّرة

```bash
node tools/build-data.js <catalog.json> "<المفتاح من CONFIG.catalogKey>" data/catalog.enc --write-token="<رمز الكتابة>"
```
حيث `catalog.json` ملف البيانات الصريح (لا يُرفع للمستودع مطلقًا — مُستثنى في `.gitignore`). معامل `--write-token` اختياري، ويُستخدم فقط عند إعادة البناء الكامل من الصفر — لتدوير الرمز في نسخة منشورة استخدم `tools/set-write-token.js` بدلًا من ذلك.

## البنية

| الملف | الوظيفة |
|------|---------|
| `index.html` | الهيكل وتحميل الخطوط والسكربتات |
| `assets/styles.css` | نظام التصميم (فاتح/داكن، RTL) |
| `js/config.js` | الإعدادات، التصنيفات، الألوان، بيانات المستودع، ومفتاح فكّ التشفير |
| `js/crypto.js` | التشفير AES‑256‑GCM / PBKDF2 (متصفح + Node) |
| `js/charts.js` | المخطط الدائري (SVG) |
| `js/icons.js` | مجموعة الأيقونات (SVG) |
| `js/app.js` | الحالة، طبقة GitHub، العرض، الفلاتر، البطاقة التفصيلية، نطاق رؤية الإدارة |
| `js/app-ui.js` | التفاعل، الحسابات والأدوار، مراجعة التعديلات، الإضافة/التعديل/الحذف، الإعدادات، بوابة الدخول |
| `tools/build-data.js` | أداة بناء الملف المشفّر من البيانات الصريحة |
| `tools/set-write-token.js` | أداة تضمين/تدوير رمز الكتابة داخل ملف مشفّر موجود |
